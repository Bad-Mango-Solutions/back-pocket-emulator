# 65816 CPU Companion

This page describes what the 65816 core must add and identifies the PocketGS
aspirations that depend on it.

**Covers:** the 65816 CPU placeholder, emulation/native register and addressing
requirements, 24-bit banked addressing, 65816 reset behavior, and the aspirational
PocketGS taxonomy, boot, and memory-map rows audited for this companion page.

**Does not cover:** a Mega II implementation, PocketGS ROM or device emulation,
PocketME/65832 behavior, or the 65832 privileged architecture. Those subjects
belong to future machine and CPU work.

types remain in `BadMango.Emulator.Core.Cpu`. The namespace names do not change

## Current 65816 implementation

**Status: Aspirational**

`Cpu65816` is a placeholder implementation. It derives from `CpuBase`, reports
65816 capabilities, and has no execution implementation:

- [`Cpu65816`](../../src/BadMango.Emulator.Emulation/Cpu/Cpu65816.cs)
- [`CpuFamily`](../../src/BadMango.Emulator.Core/Cpu/CpuFamily.cs)
- [`Registers`](../../src/BadMango.Emulator.Core/Cpu/Registers.cs)
- [`RegisterHelpers`](../../src/BadMango.Emulator.Core/Cpu/RegisterHelpers.cs)
- [`ArchitecturalMode`](../../src/BadMango.Emulator.Core/Cpu/ArchitecturalMode.cs)

> **Current location (until #562):** `src/BadMango.Emulator.Emulation/Cpu/`;
> target: `src/BadMango.Emulator.Core/Cpu/` (namespaces unchanged).

`Cpu65816.Step` throws `NotImplementedException`. `Cpu65816.Reset` throws
`NotImplementedException` as well. These methods must not be described as
runnable CPU behavior. The later #473 65816 CPU module will replace this
placeholder; the assembly fold under #562 does not implement it.

## 65816 execution requirements

**Status: Partly implemented (shared storage only)**

The shared register file and mode helpers already contain 65816 data views and
mode detection, but no 65816 instruction path executes them. In particular:

- `CP=true, E=true` is 65C02 compatibility mode.
- `CP=true, E=false` is 65816 native mode.
- The M and X flags select 8-bit or 16-bit accumulator and index widths in native
  mode.
- Emulation mode provides 6502/65C02-compatible 8-bit accumulator, index, stack,
  direct-page, and 16-bit program-counter behavior.
- Native mode adds 16-bit SP and direct-page registers plus DBR and PBR bank
  registers.

The eventual core must provide 24-bit effective addressing, bank-aware read and
write behavior, emulation/native mode changes, width-sensitive opcode and
addressing behavior, and reset/interrupt handling. The opcode-table design is
tracked separately in [`65816 Opcode Table Design.md`](../65816%20Opcode%20Table%20Design.md);
that design is not implementation status.

The shared register model is not a claim that the 65816 is implemented. The
existing 65816 WDM/opcode-table and execution work remains pending in the
same way as `Cpu65816.Step`.

## 1.1 PocketGS machine taxonomy

**Status: Aspirational**

The audited 1.1 taxonomy row identifies PocketGS as a 65C816-class machine with
a 16 MB address space and Apple IIgs target fidelity. It is a future target, not
a built machine. The Pocket2e profile is the only machine currently wired to a
real CPU implementation.

The PocketGS row must not imply that `Cpu65816` or a 24-bit machine is runnable.
Mega II, FPI, ROM, and slot behavior are separate future work and are deliberately
out of scope here.

Evidence: [Architecture Spec v1.0 Part 1, §1.1](../Architecture%20Spec%20v1.0%20Part%201.md#11-machine-taxonomy).

## 10.2 PocketGS boot sequence

**Status: Aspirational**

The audited PocketGS boot sequence is future work:

1. Hard reset returns a 65816 to emulation mode.
2. A ROM03-style path is responsible for ROM initialization and native-mode setup.
3. Hardware such as the Mega II and shadowed memory is initialized.
4. RAM is probed and sized.
5. A Control Panel choice and slot boot scan lead to booted code or BASIC.SYSTEM.

No built implementation currently performs this sequence. In particular:

- `Cpu65816.Reset` throws instead of loading a reset vector.
- There is no Mega II implementation.
- There is no ROM03 reset path.
- There is no PocketGS slot scan or boot handoff.

This page intentionally does not specify or design Mega II behavior. The boot
sequence remains aspirational until a 65816 core and a PocketGS system profile
exist.

Evidence: [Architecture Spec v1.0 Part 3, §10.2](../Architecture%20Spec%20v1.0%20Part%203.md#102-pocketgs-boot-sequence).

## A.2 PocketGS memory map

**Status: Aspirational**

The audited Appendix A.2 PocketGS row describes a 24-bit, 16 MB address map.
The following high-level regions are the archival target sketch, not an existing
memory map:

- Bank `$00`: legacy I/O and the lower 64 KB of the IIgs-compatible address space.
- Bank `$01`: auxiliary memory.
- Banks `$02-$7F`: expansion RAM.
- Banks `$80-$DF`: reserved/expansion.
- Banks `$E0-$E1`: Mega II shadowed RAM and Super Hi-Res regions.
- Bank `$FE`: ROM.
- Bank `$FF`: ROM and vectors.

The target does not add a PocketGS bus or Mega II routing implementation. Bank,
shadow, soft-switch, ROM, and video behavior are future machine/device work.
The [`65816 Emulator Reference`](../../reference/WDC%2065816%20Emulator%20Reference.md)
supplies instruction and reset-vector reference material; it does not make the
CPU implemented.

Evidence: [Architecture Spec v1.0 Appendix, §A.2](../Architecture%20Spec%20v1.0%20Appendix.md#a2-memory-map-quick-reference).
