# 65832 Companion and Privileged Architecture

The 65832 is an aspirational CPU companion: shared register scaffolding and
privilege types exist, but there is no runnable 65832 CPU, page-table walk, trap
path, or PocketME boot implementation.

**Covers:** audited privilege-register, paging, PocketME physical-map, boot, and
boot-handoff material, plus the privileged draft's trap boundary and the
aspirational PocketME memory-map row.

**Does not cover:** the as-built 65C02 CPU, bus/MMU fast-path behavior, 65832
compatibility personalities, or a copied restatement of the privileged
architecture specification. The 65832 ISA, ABI, paging rules, trap rules, and
reset contract remain in that draft.

## Code paths and target layout

In the [target assembly layout](../../specs/Solution%20Consolidation%20Design.md),
all three paths below survive in `BadMango.Emulator.Core`:

- [`Cpu65832`](../../src/BadMango.Emulator.Core/Cpu/Cpu65832.cs) keeps the
  existing `BadMango.Emulator.Emulation.Cpu` namespace. It derives from
  `CpuBase`, but both `Step` and `Reset` throw `NotImplementedException`.
  The placeholder sets `Base6502`, `SupportsEmulationFlag`,
  `Supports16BitRegisters`, and `Supports65C02Instructions`. It does not set
  `SupportsCompatibilityFlag`, `Supports32BitRegisters`, or
  `Supports65832Instructions`.
- [`SystemRegisters`](../../src/BadMango.Emulator.Core/Cpu/SystemRegisters.cs)
  already lives in the Core assembly and keeps
  `BadMango.Emulator.Core.Cpu`. It stores CR0, PTBR, VBAR, FAR, FSC, and TLS.
- [`PrivilegeLevel`](../../src/BadMango.Emulator.Core/PrivilegeLevel.cs) already
  lives in the Core assembly and keeps the `BadMango.Emulator.Core` namespace.
  It defines `User`, `Kernel`, `Hypervisor`, and `Reserved`; the first three
  levels are the architectural values carried into the bus access metadata.

Emulation lives in Core. That fold does not implement the 65832.
[`MachineBuilder`](../../src/BadMango.Emulator.Core/MachineBuilder.cs) still
rejects `CpuFamily.Cpu65832` as unsupported.

[`ControlRegisterHelpers`](../../src/BadMango.Emulator.Core/Cpu/ControlRegisterHelpers.cs)
provides CR0 bit helpers, but no CPU path calls them. They are not evidence that
privilege, paging, NX, or trap behavior is implemented.

## Opcode prefix

**Status: Aspirational**

[`65816 Opcode Table Design.md`](../65816%20Opcode%20Table%20Design.md) is the
binding opcode map. `$42` is the prefix for 65832-exclusive opcodes, and only
while `CP` is clear. `$42 xx` selects the extended bank. `$42 42 xx` is the
deeper bank. `$43` and `$44` stay the 65816 instructions `EOR d,S` and `MVP`.
They are not prefixes. While `CP` is set, `$42` remains 65816 WDM.

[Architecture Spec v1.0 Part 3](../Architecture%20Spec%20v1.0%20Part%203.md)
Phase 6 still lists prefix decoding for `$42`, `$43`, and `$44`. The
opcode-space essay also draws top-level `$43 xx` and `$44 xx` banks. Neither
is the map. `Cpu65832.Step` throws, so none of this prefix is decoded.

## Privileged architecture decision log

The architectural source is
[`reference/Privileged architecture spec v0.1 for 65832.md`](../../reference/Privileged%20architecture%20spec%20v0.1%20for%2065832.md).
This page points into that file rather than reproducing it.

The file is a decision log with concatenated v0.1 through v0.6 text. A later
delta wins where an earlier version disagrees. Use its later paging, privilege,
device-page, fault, and reset decisions rather than treating the first draft
as a frozen standalone contract.

The draft is the source for:

- 65832 modes, user/kernel/hypervisor privilege, and privileged-instruction
  boundaries;
- two-level paging, PTE permissions and device-page extensions, PTBR semantics,
  and page/device faults;
- trap entry and vectoring, including VBAR and saved trap state;
- hard/soft reset, ROM mapping, the PocketME physical map, and boot handoff.

These are design requirements, not implemented `Cpu65832` behavior.

## 2.2 Privilege Levels (65832)

**Status: Partly implemented**

`PrivilegeLevel` and the CR0 privilege bits documented by `SystemRegisters`
exist. `SystemRegisters` is embedded in the shared `Registers` value; the
storage alone does not enforce access.

No running CPU checks a user-mode system-register access, raises a privilege
trap, changes mode on trap entry, or executes a privileged instruction boundary.
The canonical bus privilege metadata also does not turn the host bus into a
65832 MMU: it is only scaffolding until an implementing CPU and access policy
use it.

The privileged draft remains normative for privilege ordering, reserved
hypervisor behavior, and trap semantics.

## 3.2 Page Table Entry Format

**Status: Aspirational**

There is no 65832 `PageTableEntry` type or page-table walker. `PageEntry` in the
bus is host routing metadata, not the 65832 architectural PTE format.

`SystemRegisters` can store PTBR and FAR/FSC values, but nothing populates them
during translation or a fault. The later PTE and device-page deltas in the
privileged draft are the authoritative design pointer.

## 3.4 Physical Memory Map (PocketME)

**Status: Aspirational**

PocketME has no assembled profile or 4 GB paged address-space implementation.
There is no 256 KB Boot ROM mapped at physical zero and no high-ROM alias.
`PhysicalMemory` remains a host-backed byte pool sized by a machine profile; it
is not the PocketME physical-memory policy.

## 10.3 PocketME Boot Sequence

**Status: Aspirational**

CR0, PTBR, and VBAR storage exists in `SystemRegisters`, but reset writes none of
them because `Cpu65832.Reset` throws. No 65832 reset state, vector fetch,
Boot ROM entry, paging bring-up, or kernel handoff runs.

The privileged draft defines those steps and their later locked deltas. A target
assembly location is not a claim that this boot path has been built.

## 10.4 Boot Handoff Structure

**Status: Aspirational**

There is no `BootHandoff` implementation and no `0x4F484D42` magic-value writer
or reader. The handoff layout and discovery contract remain examples and
decisions in the privileged draft until a real 65832 boot path owns them.

## Trap, interrupt, and exception boundary

**Status: Aspirational**

The shared 65C02 interrupt and bus-fault infrastructure is not a 65832 trap
implementation. `Cpu65832` has no trap frame, privilege/mode transition, VBAR
vector fetch, page-fault entry, syscall entry, or return-from-trap path.

Use the privileged draft for the trap contract. Keep host bus `FaultKind`
handling and 65C02 behavior on the separate CPU and bus pages rather than
copying either mechanism into this companion as though it implemented 65832
privilege.

## Appendix A.2: PocketME quick-reference row

**Status: Aspirational**

The PocketME row describing a 4 GB 65832 machine, Boot ROM at physical zero,
RAM after the ROM, and a high-ROM alias is a planning map. No current
`MachineBuilder` profile, page table, ROM object, or CPU path assembles it.
